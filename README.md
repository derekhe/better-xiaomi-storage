# 映集（Yingji）

一个面向小米智能存储的开源 Windows 相册。它为大型照片库提供时间轴、相册导航、年月日快速定位、搜索、媒体筛选、懒加载缩略图、大图预览和本机照片清理。

<img src="public/brand/app-icon.png" width="96" alt="映集应用图标" />

## 主要功能

- 按拍摄日期浏览照片时间轴。
- 直接选择年、月、日，快速跳到很久以前的照片。
- 按相册、关键字和照片/视频类型筛选。
- 点击照片查看适应窗口的原图；点击视频使用原生播放器播放和拖动进度。
- 先读取轻量照片索引，再按需加载目标附近的缩略图，适合大型照片库。
- 本机分析重复、相似、模糊和曝光异常照片，推荐保留并预览、勾选清理。
- 确认后将勾选照片移入设备回收站；不提供永久删除或上传功能。
- 直接登录小米账号、选择设备，独立建立相册连接。

## 照片清理

点击侧栏“照片清理”→“开始后台分析”。应用读取照片与收藏索引，在独立后台进程内分批计算画面指纹、颜色、清晰度和曝光。准备 LIQE 后，可选择本地 AI 画质分析，用 1–5 分的质量评分辅助同组照片选优。可以设置严格 / 标准分组以及每组保留数量；每组至少保留一张，收藏始终受保护。

后台任务会连续处理各批照片；切换页面或最小化窗口后继续运行。每 20 张保存一次加密的本地特征和评分，暂停和正常退出时保存已完成记录；重新打开后点击继续即可复用。每个任务只读取一次完整索引，照片改变或模型版本更新后补充分析。AI 只在本机运行，不上传照片；仅因 AI 画质偏低的照片不会默认勾选。清理前先暂停分析，再核对和确认选择。

点击照片检查大图，在“待清理”中复核选择，再点击“移入回收站”。Electron 会再次读取设备索引和收藏，并弹出原生确认框。每次最多处理 500 张，逐张返回成功或失败；超时不自动重试，结果不确定时需要重新分析才能再次清理。回收站空间不足也不会改用永久删除。回收站保留期间不一定立即释放空间，请在官方客户端查看或恢复。

规则算法移植自 [轻了相册](https://github.com/vickysy/qingle-album)，LIQE 推理适配自其官方 MIT 实现，署名见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。LIQE 评估画质，不是审美或纪念价值评分。当前使用预览图，并非文件哈希去重；尚未接入人脸 / 闭眼、审美模型、OCR、视频分析或视频压缩。网页样例模式仅演示规则分析，不执行删除。

本地 AI 环境需要 `uv` 和 Python 3.12，可运行 `npm run prepare:liqe` 准备 NVIDIA CUDA 环境、下载并校验公开模型；没有 NVIDIA GPU 时运行 `powershell -File scripts/prepare-liqe.ps1 -Device cpu`。环境和模型保存在忽略的 `vendor/liqe-runtime` 中，不写入 Git。准备后推理不访问外网。CUDA 环境占用较大，打包会包含独立推理环境。

照片清理可一次勾选超过 500 张。此时“清理前 500 张”只处理当前一批，并弹出确认框；其余照片保留勾选，可继续下一批。每批完成后继续保留你手动选择的照片。

## 安装与使用

系统要求：Windows 10/11，以及已绑定小米账号的小米智能存储设备。

预发布版 `0.2.0-alpha.1` 接入独立登录：完整安装包携带所需的原生登录/P2P组件，无需另外安装官方客户端。已验证组件启动及模拟账号界面流程；真实账号登录、证书签发和设备读取仍待联调。正式版 `0.1.1` 仍使用官方客户端通道。

1. 从 [Releases](https://github.com/derekhe/better-xiaomi-storage/releases) 下载最新的 `better-xiaomi-storage-*-setup.exe`。
2. 运行安装程序。当前安装包未进行商业代码签名，Windows SmartScreen 可能显示“未知发布者”；请只从本仓库 Release 下载，并按下方方法核对 SHA-256。
3. 使用新的独立登录构建时，启动映集，点击“登录小米账号”，在弹出的小米登录窗口中完成登录和验证。现有正式版仍需先打开并登录官方客户端。
4. 独立登录构建中选择要连接的存储设备，即可打开相册；之后可以按需建立完整的轻量时间索引。
5. 点击顶部的时间定位，依次选择年份、月份和日期，即可跳转到对应位置。

校验安装包（将文件名替换为实际版本）：

```powershell
Get-FileHash .\better-xiaomi-storage-0.1.0-setup.exe -Algorithm SHA256
Get-Content .\SHA256SUMS.txt
```

两处哈希值必须完全一致。

## 常见问题

- 独立登录时提示端口被占用：关闭正在运行的官方客户端，再在映集中登录。原生组件使用固定的本机端口，两者不能同时运行。
- 独立登录后连接失败：确认设备在线、登录账号已绑定该设备，再重新选择设备。账号验证和设备证书仍由小米服务完成。
- 现有正式版提示“尚未找到设备证书”或“未找到设备通道”：保持官方客户端运行，进入一次官方相册后，在映集中点击重连。
- 时间定位首次加载较慢：应用正在获取轻量索引，不会同时下载全部缩略图；之后定位只加载目标附近内容。
- SmartScreen 警告：0.1.0 尚未代码签名。请只使用 GitHub Release 中的文件并验证 SHA-256。

## 隐私与安全边界

- 浏览和分析调用相册索引、缩略图和媒体读取接口。清理仅在用户确认后调用 `del_photo` 接口（`notrash: 0`），将所选照片移入设备回收站。
- 独立登录使用随安装包附带的官方原生登录/P2P组件；映集负责组件进程、设备选择、证书生命周期和读取通道。尚未重写原生 P2P 协议。
- 小米账号密码和登录验证在小米窗口中输入。应用不读取、复制官方客户端的 Cookie 或已有账号缓存。
- 映集保存的登录会话及设备私钥使用 Electron `safeStorage` 的 Windows 凭据加密，证书和密钥只在主进程内用于 HTTPS；不会传给相册页面。
- 原生登录组件另有独立的浏览器/SDK缓存和日志。退出账号会清除本应用会话并尝试删除这些缓存；若 Windows 文件锁暂时阻止清理，下次登录会使用新的独立目录。原生组件的内部行为仍需进一步验证。
- 原图和视频通过映集管理的本机 WebDAV 隧道按需读取；临时用户名和密码仅保存在 Electron 主进程内存中，不会传给页面。
- 连接探测只检查 `get_access_token` 的结果是否含令牌，令牌不保存或用于后续相册请求。
- 页面启用上下文隔离、禁用 Node 集成，并通过受限 IPC 接口访问本机设备通道。
- 清理 IPC 在主进程校验数量、路径、相册归属和收藏，默认取消的原生确认框关闭后才发出删除请求。
- 清理期间禁止切换设备、退出账号或重连；设备连接变化会要求重新分析。切换设备后清空上一台设备的清理结果。

本仓库不包含用户证书、私钥、令牌、设备 ID、照片或运行日志。原生组件位于被 Git 忽略的 `vendor` 目录。独立登录并不要求安装完整的官方客户端，但仍依赖这些原生组件。

## 开发

需要 Node.js 20 或更高版本。

```powershell
npm ci
npm run prepare:runtime
npm run dev
```

`prepare:runtime` 默认从本机官方客户端的安装目录导入组件，也可用 `npm run prepare:runtime -- --source <目录>` 指向官方安装包解压后的 `resources/extraResources/windows`。导入只允许程序、DLL、静态资源、SDK配置和公共 CA 链，不复制用户缓存、Cookie、日志或证书。组件包含独立的 SHA-256 清单，启动时检查完整性；完整安装包将携带组件，最终用户无需执行此步骤。

原生组件保留其原有许可，公开分发前应核实相关组件的分发条件。源码的 MIT 许可证不覆盖这些组件。

单独查看相册界面可运行 `npm run dev:web`，此时使用不含个人信息的样例数据。

```powershell
npm test
npm run build
npm run package
```

网页产物位于 `dist/renderer`，Windows 安装包位于 `release`；两者都不会提交到 Git。

维护者发布前应执行测试、构建、依赖与凭据扫描，并确认安装包中的 `app.asar` 只包含运行所需文件。
